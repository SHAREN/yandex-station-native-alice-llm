# Native Alice TTS streaming audit and natural punctuation policy — 2026-11-04

**RESOLVED on 2026-11-04:** Live isolated UniProxy experiment confirmed streaming text synthesis works using `TTtsGenerate.IsStreaming=true` (field 12) followed by `TDeferredTtsGenerate` (event field 34; `Text`, `RequestMessageId`, `IsLast`, `ChunkNum`). A non-final text fragment produced Opus audio **before** the final fragment; all audio used the same stream ID. The earlier 'not proven' and 'schema conflict' statements below are historical only. See the definitive `docs/NATIVE_TTS_STREAMING_CONFIRMED_20261104.md`.

## Scope and finding
User reported that independent per-sentence Yandex TTS requests reset their prosody: a cut in the middle of a sentence is heard as an artificial end/new start. They asked whether stock Station Lite 1 can receive an *incrementally growing text stream in the same TTS session*, and requested grammatical punctuation preference for any fallback segmentation.

**Alternative that is demonstrably available but is not the same stock path:** Yandex SpeechKit API v3 `Synthesizer.StreamSynthesis` accepts options once and subsequent `SynthesisInput(text)` on one gRPC stream; supports `general` and `livetts` and OGG_OPUS output. Official docs: https://aistudio.yandex.ru/ru/docs/speechkit/tts/api/tts-streaming and https://aistudio.yandex.ru/en/docs/speechkit/tts-v3/api-ref/grpc/Synthesizer/streamSynthesis . It requires independent Yandex Cloud service-account auth, its exact voice may differ from stock Alice, and it is not known to reuse the Station account's token. It could feed the *existing* audio player through Bridge if explicitly selected, with auth/latency/prosody tests; no credentials were accessed and no network synthesis request was sent in this investigation.

**Verified on physical Lite 1** (root ADB `192.168.0.19:5555`, firmware `/system/vendor/quasar/maind`, approximately 20.8 MiB): runtime binary strings contain `NAlice.NAliceApi.TTtsGenerate.Text`, `handleTtsGenerate`, `TtsSpeak`, `lazy_tts_streaming`, and the embedded protobuf type `NAlice.NAliceApi.TDeferredTtsGenerate` with `RequestMessageId` and `Text`. Searching symbol strings did not show a corresponding `handleDeferredTtsGenerate` handler. This is static evidence of *some* protobuf vocabulary, **not** proof of accepted, live incremental TTS input.

**Verified in the vendored AAPI protobuf** (`github.com/freequasar/quasar-go-genproto` as used by this project): `TTtsGenerate` has a single `Text` field and ordinary voice/speed/format options. `RealtimeStreamer` is a reserved legacy field in its descriptor, with no supported value. The generated client schema does not expose a `DeferredTtsGenerate` event. The current stock `TtsSpeak`/Opus binary stream is streaming *audio*, which must not be confused with streaming *text input*. `DeferredAliceResponse` supports partial answer text but does not automatically append it to an active `TTtsGenerate`.

**Yandex cloud supports it in another API:** SpeechKit API v3 `Synthesizer.StreamSynthesis` is bidirectional streaming: send `SynthesisOptions` once, then many `SynthesisInput(text=...)` entries in a single session. Source: https://aistudio.yandex.ru/ru/docs/speechkit/tts/api/tts-streaming and https://yandex.cloud/ru-kz/docs/speechkit/tts-v3/api-ref/grpc/Synthesizer/streamSynthesis . This **does not prove** the Lite 1 firmware exposes that cloud API over its existing Alice/uniproxy connection, uses the same voice, or permits transparent reuse of the account. SpeechKit docs also explain that synthesis uses text context to choose natural prosody: https://aistudio.yandex.ru/ru/docs/speechkit/tts/ .

**Updated definitive finding (2026-11-04, binary case-table audit):** `kDeferredTtsGenerate` exists in the compiled **client → server** event table of the exact physical Lite 1 `maind`, alongside `kVoiceInput`, `kAsrRecognize` and `kTtsGenerate`; it is *absent* from the **server → client** event table (which contains `kTtsSpeak` and `kDeferredAliceResponse`). Therefore it is **not** an inbound command to append text to the speaker's stock TTS. The cloud-side semantics of this outgoing deferred request remain unknown; do not infer continuous prosody merely from `Text` + `RequestMessageId`. Full evidence, offsets, reproducible read-only script, and firmware SHA: `docs/DEFERRED_TTS_FIRMWARE_DEFINITIVE_AUDIT_20261104.md`.

**Decision:** Keep using the confirmed stock `TTtsGenerate` / `TtsSpeak` / Opus player. Do not fabricate unsupported incoming `DeferredTtsGenerate` messages or switch to separately authenticated cloud TTS without a compatibility and same-voice audit. Treat genuinely continuous-text-native TTS as an open research branch requiring a verified cloud-side implementation or isolated experiment.

## Deployed natural-boundary fallback (Quasar Bridge 0.4.5d)
- The first emitted fragment starts at a complete short sentence (`.`, `!`, `?`, `…`) when available. If the opening sentence is lengthy, instead use its *first natural breathing pause* (comma, semicolon, colon) **after at least 55 Unicode runes**, not a fabricated full stop.
- **Subsequent fragments prioritize sentence endings**, keeping any normal clause commas inside the same TTS input. If a subsequent sentence grows beyond 300 runes, use a native comma/semicolon/colon after at least 115 runes; otherwise wait for the actual sentence ending.
- There is **no longer an arbitrary split at ~430 runes or any word boundary**. If a generated sentence is entirely unpunctuated it remains intact until the model provides punctuation or completes; this is an intentional prosody/latency trade-off.
- Do not split the decimal separator of a number, including streamed `3,` + `14` or `3.` + `14`.
- The predictive scheduling from 0.4.5c is unchanged: stock TTS only; queue completed text chunks; 60%/3-second planning reserve; combine up to two ready short sentences where possible; one native audio stream without overlapping voices. **Separate TTS calls can still reset prosody** even at a comma: a punctuation boundary is mitigation, not a guarantee of perfect continuation.

Examples:
1. `Григорий пришёл.` -> synthesized as one full sentence.
2. `В одной далёкой деревне возле заснеженного соснового леса, где старый часовщик проводил вечера за работой.` -> first segment `В одной далёкой деревне возле заснеженного соснового леса,`; next segment `где старый часовщик проводил вечера за работой.`.
3. Subsequent regular sentence with commas -> keep intact until `.`.
4. Long text without punctuation -> never split at a random word.
