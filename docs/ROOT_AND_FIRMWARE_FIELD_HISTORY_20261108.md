# Яндекс Станция Lite 1: проверенная история root, прошивки и перехода к Native Alice + LLM

**Сводка составлена 08.11.2026.** Основана на завершённом эксперименте 25–27 октября, локальных протоколах/манифестах и состоянии проекта 04–07 ноября. Это история **одной конкретной Lite 1 (YNDX-00025, `yandexmicro`)**, а не инструкция для произвольной модели.

> Не содержит идентификатора устройства, MAC, внутренних адресов, приватных ключей, токенов, дампов flash или материалов аккаунта. Первичные доказательства и аварийные образы хранятся только вне колонки в частном хранилище владельца.

## 2. Почему сработал именно этот маршрут

1. Свежая прошивка могла отклонять TLS-сертификат стенда (`TLSV1_ALERT_UNKNOWN_CA`): корректная DNS-подмена не равна успешной активации ADB.
2. Factory загрузила поддерживаемую базу, но ожидает обновления. Постоянное `hasUpdate=false` мешает получить совместимую .46.
3. Использован **свой локальный сервер** с модельным OTA, журналами фактических запросов, проверкой TLS, полного скачивания, Range и хеша. Внешний DNS `179.254.167.126` был частью ранних неудачных попыток, но **не является доказанной причиной успеха**.
4. Только для `yandexmicro` раздан официальный подписанный `0.369.1.46.4778262442.20261013.297`, 66 814 464 байта; SHA-256 `74d4e8fae375b2ad1757761e01caf6be0209d216328ce1a942dbef38c8f20d11`. Файл назван `.zip`, хотя начинается с `070702` (cpio); нельзя перепаковывать подписанный образ из-за непривычной сигнатуры.
5. Уже на .46 колонка сама запросила sync-настройки и стала доступна по root ADB. Это ключевой проверенный переход.

Основные ошибки повторения: не тот каталог `firmware/yandexmicro/`/manifest на стенде; выдача чужой модели OTA; DHCP/DNS подмена сразу для всего дома вместо конкретного клиента; сброс без готового HTTP/HTTPS/TLS; спутывание ответа тестового сервера с запросом реальной колонки; повторное использование установщика с зашитыми прежними IP/ID.

## 3. Что именно было закреплено после root

- SSH root по отдельному ключу на порту 2222 с отключённой парольной авторизацией; fingerprint хоста и ключи для каждой колонки индивидуальны.
- Проверка исходного root ADB, ключевого SSH, отказа небезопасного логина и повторная проверка после **настоящей перезагрузки**.
- Сохранение оригиналов конфигурации запуска/OTA вне устройства, удаление активной задачи `updatesd` из startup и модельно-проверенные меры запрета OTA.
- После финальной проверки — снятие временных подмен DNS, возврат обычного маршрута запросов и остановка временного стенда. Работающий постоянный домашний DNS/роутер при этом не отключались.
- Бэкап исходных разделов и важных файлов с манифестом SHA-256. **Ограничение:** дамп bootloader частичный из-за ECC/read error; `bkupgrade` получен с живой файловой системы и не является консистентным offline-снимком. Не называть такие файлы полностью восстановимым образом.
- Идентификацию устройства проводить по platform + ID/MAC и актуальному mDNS/DHCP, а не по когда-то закреплённому IP.
- Изменения на прочих моделях выполнять отдельно, не переиспользовать автоматически образ Lite и её скрипты.

## 4. Текущее устройство и архитектура: не путать с перепрошивкой

**Root/OTA** — нижний уровень доступа к заводской Linux-системе. **Native Alice + LLM** — приложение поверх штатного `maind`/UniProxy, а не наша новая системная прошивка.

```text
Голос → штатные wake/VQE/ASR → Quasar Bridge
  ├─ штатные команды → облачная Алиса
  └─ текстовый вопрос → LLM relay → смысловые фрагменты
      → TtsGenerate(IsStreaming=true, Text="")
      → DeferredTtsGenerate(ChunkNum=1..n, IsLast=false)
      → финальный IsLast=true
      → штатный Yandex TTS / Opus / плеер
```

В принятой 05.11 сборке первая часть ждёт естественную паузу; следующие чанки — законченные предложения. Одна **сетевая** TTS-сессия не означает один Ogg-сегмент и не доказывает идеальную склейку интонации. Проигрывание было принято человеком на физической колонке. Время от конца вопроса до первого звука 1–2 с — **цель исследования, не подтверждённое свойство**.

Не смешивать этот проект с отдельным экспериментальным [Gemini Live Bridge](https://github.com/SHAREN/yandex-station-gemini-bridge). Быстрые команды, управление громкостью/музыкой/таймерами нужно прежде всего делегировать штатному обработчику, а не воспроизводить на стороне LLM. Прямой Home Assistant и поиск в собственных assistant-tools на 07.11 оставались **выключены**; двухфразовый внешний fastcommands — отдельный компонент.

## 5. Эксплуатационные правила и актуальный откат

- **Никаких долгоживущих `*.bak`, предыдущих бинарников и OTA-копий на колонке.** На самой станции только актуальный runtime; временный `/tmp` служит staging с обязательной очисткой после операции. Бэкапы и SHA-манифесты — на Home PC или Home Server.
- Не удалять `/data/opt/quasar-bridge/endpoint-backup.json`: это **действующее состояние аварийного fail-open**, используемое `S98zzbetteryam`, а не архивный мусор.
- Перед каждым обновлением и после него: проверка свободного UBI, ожидаемого размера нового файла, SSH/root, `healthz`, WebSocket, штатных голосовых запросов, возврата DNS и стабильности после холодного старта. При прогнозируемом остатке UBI менее 25 МиБ деплой запрещён.
- **Важное исправление старых инструкций:** ранние файлы описывают откат к `/tmp/quasar-bridge-0.4.5f.gz`. После уборки **07.11.2026 этой копии на колонке больше нет**. Сначала получить оригинальный бинарник из проверенного внешнего архива, сверить SHA-256, временно перенести в `/tmp`, затем выполнить штатный откат только Bridge и очистить staging.
- Не изменять системные `maind`/медиастек и не отключать аутентификацию Home Assistant для ускорения интеграции.
- Не публиковать в GitHub реальные IP, устройства/аккаунты, секреты SSH, сертификаты, дампы, токены и журнал разговоров.

## 6. Чего ещё не хватает и что важно исследовать

| Тема | Текущий статус |
| --- | --- |
| Строгий протокол восстановления всей системы из backup | Не доказан; учитывать частичный bootloader и live UBI. |
| Root на Lite «Ванная», Mini 1 «Зал», Mini 2 «Кухня» | Не переносить статус успешной «Комнаты» на остальные; для Mini 1 рассмотреть USB/TPL, для Mini 2 — собственную .46, отдельную SSH-проверку. |
| Cold boot, перебивание ответа, штатные команды в разных режимах, latency по стадиям | Отдельные тесты, а не часть принятой 05.11 озвучки. |
| Классификация шёпота | Нужна трассировка места классификации (локальная VQE/ASR или сервер); предположение о локальном детекторе — не доказательство. |
| Поиск Brave/Tavily и LAN Home Assistant | Есть код и offline-тесты, но релиз на 07.11 блокирован; в рантайме не объявлять работающими. |
| 30-дневный журнал запросов/ответов за пределами станции | Сейчас журнал ограничен несколькими мегабайтами, постоянный внешний архив ещё не включён. |
| Native GPT Realtime/full duplex | Исследовательское направление; **не** то же самое, что уже работающий текстовый UniProxy/TTS. |
