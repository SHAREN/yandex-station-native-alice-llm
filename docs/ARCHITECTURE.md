# Архитектура Native Alice + LLM

## Что мы модифицируем

Это модифицированный **Quasar Bridge**. Оригинальная прошивка `maind` и `mediad` остаётся штатной и доступной только для чтения. Bridge работает на колонке как промежуточный UniProxy/AAPI сервис. Отдельный Home PC релей получает текстовые запросы к выбранной нейросети.

**Это не Gemini Live:** пользователь говорит в штатный микрофон Алисы, распознавание выполняет штатный Yandex ASR, ответ синтезирует штатный Yandex TTS с родным голосом. Отдельный аудио-LLM и двусторонний Live-поток отсутствуют.

## Разделение маршрутов

1. «Яндекс» активирует штатный обработчик, затем штатный ASR распознаёт команду.
2. Bridge проверяет маршрутизацию. Штатные действия (музыка, таймеры, управление громкостью) остаются в оригинальном облачном маршруте Алисы.
3. Для обычного вопроса используется GPT-релей. Результат потоково приходит текстом.
4. По мере генерации ответа GPT Bridge ждёт **первой готовой смысловой границы**: точки, `!`, `?`, многоточия или естественной запятой/двоеточия/точки с запятой после ~32 символов. Тогда открывает ровно одну сессию UniProxy через `TtsGenerate{Text:"",IsStreaming:true}` (AAPI field 13, IsStreaming field 12). При IsStreaming=true **исходное поле Text сервер игнорирует** (проверено реальным синтезом).
5. **Все произносимые слова, начиная с самых первых**, отправляются как `DeferredTtsGenerate` (AAPI client event field 34) с одним и тем же `RequestMessageId`, возрастающим `ChunkNum` и `IsLast=false`. Первый чанк — до подходящей естественной паузы, затем **одно предложение на каждый чанк**. При необычно длинном предложении (800+ символов) допускается дополнительная пауза; произвольные 16-символьные разрезы запрещены. Пробелы и пунктуация сохраняются побайтово. Новая серверная `TtsGenerate` на каждое предложение **не** создаётся.
6. На конце ответа отправляется IsLast=true; пустой завершающий сегмент допускается (подтверждено реальным isolated UniProxy тестом).
7. UniProxy выдаёт один **сетевой** аудиопоток `TtsSpeak` и может поместить в него несколько **логических** Ogg/Opus-последовательностей — это подтверждено измерениями штатной Алисы. Bridge передаёт оригинальные байты штатному плееру без перекодирования или самодельной склейки, а в конце — один `StreamControl.Close`. Это не доказывает полного сохранения интонации между отдельными акустическими сегментами.

## Надёжность

- Старый последовательный синтез сохранён за отключённым feature flag.
- Feature flag включён наличием файла `/data/opt/quasar-bridge/enable-native-streaming-tts`. Для новых запросов выключается удалением файла, без перепрошивки.
- Исходная система не редактируется, только пользовательский бинарник Bridge.
- После сборки sentence-tts-20261105 подтверждены тесты `go test ./...`, новый SHA256 бинарника, здоровье `healthz=ok` и живой WebSocket. Физическое звучание (длинный рассказ, плавность, паузы, окончание, «стоп» и перебивание) ещё требует проверки на слух.

Потоковый протокол доказан: [NATIVE_TTS_STREAMING_CONFIRMED](NATIVE_TTS_STREAMING_CONFIRMED_20261104.md). Историческая сборка 0.4.5f: [NATIVE_TTS_CUTOVER](NATIVE_TTS_CUTOVER_20261104.md). Установленное состояние sentence-tts-20261105: [CURRENT_STATE](CURRENT_STATE.md).
