# Прямые команды Алисы → Home Assistant: подготовка без Yaha Cloud

Дата: 06.11.2026. **Статус: НЕ РАЗВЁРНУТО, новые команды на физической колонке НЕ включены.**

## Решение владельца

Не изменять и не использовать Yaha Cloud в рамках нового маршрута. На 06.11 Yaha Cloud возвращён в первоначальный список 27 устройств (без групп `light.lampy_komnata` и `light.torshery`, прежняя центральная сущность присутствует, но новый прямой путь никогда не должен её трогать).

## Желаемый маршрут (исходная прошивка сохраняется)

Штатные wake-word и `aliced` → финальный `AsrResult` в уже установленном Quasar Bridge → `fastintent.Match` (строгая фраза) → LAN-only Home Assistant webhook automation со статическими allowlist-целями `light.lampy_komnata` / `light.torshery` → штатный UniProxy TTS при необходимости.

- **Без LLM** для точного совпадения, обычные вопросы по прежней маршрутизации.
- Уже работающий отдельно установленный `alice-ha-fastcommands` продолжает независимо выполнять только две команды **без wake-word**: `включи свет` / `выключи свет`.
- Нельзя вызывать `switch.vykliuchatel_komnata_center`: это технический канал питания ламп.
- Не создавать второй ASR, свой wake-word, собственный проигрыватель, изменённый `maind` или облачный путь через Yaha.
- Веб-хук Home Assistant допустим только с `local_only: true`, `allowed_methods: [POST]`, секретом не менее 64 криптографически случайных hex-символов, **только для безопасного освещения**. Секрет не хранить в публичном Git или логах.
- Сам HA webhook по HTTP 2xx подтверждает **приём**, но не физическое включение лампы. Ответ агента должен быть «Команда отправлена», пока не добавлено подтверждение состояния. Никаких автоматических повторов команды при сбоях сети.

## Что готово в исходниках

`src/quasar-bridge/internal/home/webhook.go`: опциональный LAN-only клиент `home.WebhookFast`, не требует административного токена Home Assistant и никогда не принимает произвольный `entity_id` из речи. Только строго типизированные `operation`, `room`, `color`, `percent`, `kelvin`. Прямой endpoint ограничен адресом Home Assistant `192.168.0.136:8123` и путём `/api/webhook/<64hex>`. Тесты в `webhook_test.go` проверяют локальный запрос, безопасный отказ, отсутствие повторных вызовов и отказ при неверной конфигурации.

**Не хватает двух обязательных этапов:**
1. В `cmd/quasar-bridge/main.go` подключить `home.NewWebhookFastFromEnv()` в `engine.Home` только при `QUASAR_FAST_HOME_ENABLED=1`. Сейчас конструктор **не вызывается**, код не оказывает эффекта. Инструмент CodexPro отказал при попытке правки `main.go` с ошибкой **Secret-looking content is blocked from edit**. **Не обходить защиту** обходным способом/файловой подменой; согласовать безопасный штатный способ работы с защищённым файлом.
2. Создать и проверить локальную HA-автоматизацию с allowlist двух групп света и соответствующей POST-схемой; она пока **НЕ создана**, webhook secret пока **НЕ сгенерирован**. Только после проверки и включения — развернуть новую версию Bridge.

Развёртывание особенно рискованно из-за флеш-места станции: 06.11 на UBI ~11 МБ свободно, действующий Bridge 24 МБ. Прежде чем заменять, требуется отдельная безопасная последовательность staging/backup/rollback, контроль SHA, health, сохранение штатных TTS/ASR. **Не перезаписывать запущенный Bridge без доказанного отката.**
