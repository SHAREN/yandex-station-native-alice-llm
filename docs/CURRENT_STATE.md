## Новая стратегия синтеза по смысловым фрагментам

- До 05.11 первый и последующие текстовые дельты передавались как
  `DeferredTtsGenerate` примерно каждые 16 символов. Это приводило к
  множеству независимых Ogg/Opus-последовательностей и слышимому перезапуску интонации.
- Теперь первый короткий фрагмент отправляется **после точки, вопросительного/
  восклицательного знака или многоточия**. Если первая фраза длинная — уже на
  естественной запятой/двоеточии/точке с запятой после ~32 символов,
  чтобы голос начал звучать раньше.
- Затем каждое **завершённое предложение — отдельный TTS-чанк**.
  Только необычно длинный фрагмент (800+ символов) допускает
  дополнительную разбивку на естественной паузе.
- Существующие функции `streamedSentenceBuffer` и `streamedSentenceEnd`
  переиспользованы. При отправке native-TTS сохраняются все символы,
  включая пробелы и знаки препинания. Неполные пары «...» ждут закрывающую кавычку.
- Сохраняется **одна** штатная серверная сессия:
  `TtsGenerate(IsStreaming=true,Text="")`, затем
  `DeferredTtsGenerate(RequestMessageId,Text,ChunkNum,IsLast=false)`
  на каждую готовую фразу, и одна финальная пустая `IsLast=true`.
  При этом каждая синтезированная часть может быть отдельной **логической**
  Ogg/Opus-последовательностью, хотя сетевой `TtsSpeak` остаётся один.
- В запасной реализации (при выключенном native-TTS-флаге) также перестали
  объединяться два коротких предложения в один сегмент.

  `DeferredTtsGenerate` исследованы до внедрения; не добавлялись новые
  аудио-драйверы, отдельный TTS или самодельная акустическая склейка.
